解决Github访问慢的问题

沈故2025-10-13frontEndGithub

GitHub 打开慢、甚至长时间连不上，让人心情很崩溃😭...github总是进不去，甚至卡死在界面，不是443就是404 not found。其实不是你网络坏了，而是“访问路径”出了问题，下面给写一套2025年最新实测有效的简单解决方案（四种不同的方法）。

修改 Hosts 文件（最快见效）

原理：绕过 DNS 污染，直接指向 GitHub 可用 IP。

步骤：

  1. 打开这个网站： https://www.itdog.cn/ping/github.comopen in new window 选一个延迟最低的 IP，比如：20.27.177.113

  2. 修改 hosts 文件：

    提示

    如果你用的是记事本，必须以管理员身份运行，否则保存会失败。

    • Windows：C:\Windows\System32\drivers\etc\hosts
    • Mac/Linux：/etc/hosts

  3. 添加一行（注意替换成你测出来的 IP）：

    # === 手动添加 GitHub 映射 ===
20.27.177.113    github.com

  4. 保存后，到powershell刷新 DNS：

    Windows命令

    ipconfig /flushdns

    Mac命令

    sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder

  5. 重新打开 GitHub，大概率秒开。

注意

GitHub IP 会变动，如果哪天又慢了，重复上面步骤换 IP 即可

使用镜像站（应急用）

如果你只是下载代码，不登录账号，可以直接用镜像站：

镜像站用法
https://kkgithub.comopen in new window把 github.com 换成 kkgithub.com
https://github.com.cnpmjs.orgopen in new window同上，适合 git clone

示例：

git clone https://github.com.cnpmjs.org/用户名/仓库名.git

配置代理（最稳定）

如果你有科学上网工具（如 Clash、V2Ray），可以让 Git 走代理：

1. 设置代理（以 Clash 为例，端口 7890）：

git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

2. 只对 GitHub 生效（推荐）：

git config --global http.https://github.com.proxy http://127.0.0.1:7890
git config --global https.https://github.com.proxy http://127.0.0.1:7890

3. 取消代理（如果哪天不用了）：

git config --global --unset http.proxy
git config --global --unset https.proxy

SSH 换端口（解决 git push 超时）

如果你用 SSH 方式克隆仓库，经常提示：

ssh: connect to host github.com port 22: Connection timed out

解决方案：改用 443 端口

编辑 ~/.ssh/config 文件，添加：

Host github.com
  Hostname ssh.github.com
  Port 443

保存后重新测试：

ssh -T git@github.com

用 GitHub Desktop（图形界面稳）

如果你不想折腾命令行，GitHub Desktop 在国内网络下表现更稳定，自动走系统代理，适合推送/拉取代码

❌ 不建议的做法

  • ❌ 反复刷新网页（没用）
  • ❌ 重启路由器（不是你家网的问题）
  • ❌ 用百度搜“GitHub 打不开”点广告（容易下到垃圾软件）

总结

先改 hosts → 再配代理 → SSH 换端口 → 镜像站应急
